## 작업 요약

기획서 Phase 10.1(PWA 적용)을 충족하는 최소 구성을 도입했다. `public/`에 manifest/icon/service worker를 추가하고, 운영 환경에서만 SW를 등록하는 PwaRegister 컴포넌트와 오프라인 fallback 라우트를 신설했다. `next-pwa` 같은 외부 의존성 없이 수동 구성으로 정적 자산 cache-first / 페이지 navigation network-first → fallback 흐름을 구현해 빌드 영향과 운영 부담을 최소화했다.

## 변경된 파일

- `public/manifest.json` (신규) — 한국어, `display: standalone`, theme/background 색상, icon SVG 한 개로 maskable + any
- `public/icon.svg` (신규) — 디자인 시스템 토큰 기반 PlayCard 브랜드 마크(앰버 카드 + 골드 번개)
- `public/sw.js` (신규) — install/activate/fetch 라우팅, 캐시 버전닝, navigation/static/API 흐름 분기
- `src/components/layout/PwaRegister.tsx` (신규) — `NODE_ENV=production` 가드 + `load` 이벤트 이후 `serviceWorker.register('/sw.js')`
- `src/app/layout.tsx` — Next 14 Metadata API로 manifest/themeColor/appleWebApp/icons 통합, `viewport` 분리, `<PwaRegister />` 마운트
- `src/app/offline/page.tsx` (신규) — 오프라인 fallback 정적 페이지

| 파일 | 위치 | 이유 |
| ---- | ---- | ---- |
| `public/sw.js` | fetch 이벤트 라우팅 (navigation → network-first 후 `/offline` fallback, `/api` 미개입, 정적 자산 cache-first) | 분기 변경 시 의도치 않은 API 캐싱·페이지 정상 로드 불가 등 운영 영향 발생 |

| `src/app/layout.tsx` | `metadata.manifest`, `viewport.themeColor`, `appleWebApp`, `<PwaRegister />` 마운트 | Next 14 Metadata API 규약. 일부만 제거하면 install banner / iOS 홈 화면 추가 동작 깨짐 |
