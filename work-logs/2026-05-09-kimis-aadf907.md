## 작업 요약

PC-15 도입 OAuth/이미지 흐름의 운영 위생 두 가지 처리. 구글 OAuth 콜백에서 `email_verified === false`인 응답을 가입 거부하고 `/login?google_error=email_not_verified`로 리다이렉트(검증된 이메일만 우리 DB에 들어오도록), 클럽 커버 이미지가 Cloudinary URL이면 자동으로 `f_auto,q_auto,c_fill,w_NNN` transform segment를 끼워넣어 WebP 변환 + 사이즈 다운 + lazy loading 적용해 카드 그리드 로딩 부담 절감. Cloudinary URL이 아니면 원본 그대로 통과해 외부 이미지 호환성도 유지.

- `src/app/api/auth/google/callback/route.test.ts` — 미검증 이메일 거부 + 검증된 이메일 통과 테스트 2건 추가

## 건드리면 안 되는 부분

| 파일 | 위치 | 이유 |
| ---- | ---- | ---- |
| `src/app/api/auth/google/callback/route.ts` | `if (info.email && info.email_verified === false)` 가드 | 이메일이 없는 케이스(드물지만 가능)는 거부하지 않고 통과. 단순히 `=== false`만 보면 `undefined` 케이스도 거부되어 검수 통과한 정상 사용자가 막힐 수 있음 |
| `src/lib/cloudinaryTransform.ts` | `KNOWN_TRANSFORM_PREFIXES` 정규식 | Cloudinary transform 키 prefix 알려진 목록. 새 transform을 도입하면 이 목록도 같이 늘려야 이미 적용된 URL을 정확히 감지 |
| `src/lib/cloudinaryTransform.ts` | `CLOUDINARY_HOST_PATTERN` (`https://res.cloudinary.com/<cloud>/image/upload/`) | 이 패턴 외 URL은 모두 원본 통과. 패턴을 좁히거나 완화하면 외부 이미지에도 transform이 끼어들어 깨질 수 있음. 운영에서 다른 호스트 사용 시 함께 갱신 필요 |
| `src/lib/cloudinaryTransform.ts` | "이미 transform 있으면 원본 통과" 분기 | 어드민/운영자가 이미 명시적으로 transform이 들어간 URL을 저장한 경우(드물게) 코드가 또 끼어들어 `/upload/f_auto,q_auto/v1/.../w_320,c_fill/...`가 되어 동작 불능. 빼면 실서버 일부 이미지가 깨질 수 있음 |
