## 작업 요약

테스트용 userId 직접 입력 세션 → 카카오 + 구글 소셜 OAuth로 로그인 진입점 전환. 두 프로바이더 모두 self-rolled 플로우(authorize 302 → state 쿠키로 CSRF 방지 → token 교환 → /v2/user/me 또는 /v1/userinfo → User upsert → 30일 세션 쿠키)로 통일. `User` 모델에서 `kakaoId` required 제거 + sparse unique 인덱스, `googleId`/`email` 신규 sparse 인덱스로 두 프로바이더 동시 지원. 로그인 페이지는 두 OAuth 버튼이 메인 진입점, 기존 평문 userId 폼은 "개발/관리 도구 열기" 토글 안으로 격리. `useSearchParams`는 Suspense로 감싸 build prerender 통과. 로컬 검증에서 `redirect_uri_mismatch`(NEXT_PUBLIC_APP_URL 오타 :300) → `invalid_client`(Kakao Client Secret ON인데 env 누락) 두 환경설정 이슈는 `.env.local` 보강으로 해결, 두 프로바이더 모두 실 동작 확인.

## 건드리면 안 되는 부분

| 파일 | 위치 | 이유 |
| ---- | ---- | ---- |
| `src/app/api/auth/{kakao,google}/callback/route.ts` | `state` 쿼리 vs `stateCookie` 비교 분기 | CSRF 방지 핵심. state 검증 누락 시 외부 사이트가 임의 쿠키 주입으로 다른 사용자 세션 탈취 가능 |
| `src/app/api/auth/{kakao,google}/callback/route.ts` | `redirectToLogin` 시 state 쿠키 즉시 삭제 (`maxAge: 0`) | 1회용 state. 재사용 방지를 위해 모든 출구에서 삭제. 누락 시 같은 state로 여러 번 callback 호출 가능 |
| `src/app/api/auth/{kakao,google}/callback/route.ts` | 기존 `nickname`/`displayName` 보존 로직 (`existing.nickname ? {} : { nickname }`) | 사용자가 클럽에서 쓰는 이름이 카카오/구글 표시명과 다를 수 있음. 매 로그인마다 덮어쓰면 닉네임이 원복됨 |
| `src/lib/{kakao,google}OAuth.ts` | `resolveAppUrl` — env 우선, 폴백으로 request 호스트 추출 | env 누락 시 동작은 하되 콘솔 등록 redirect URI와 불일치하면 `redirect_uri_mismatch`. NEXT_PUBLIC_APP_URL을 운영 도메인으로 명시하는 게 안전 |
| `src/lib/models/User.ts` | `kakaoId` / `googleId` 인덱스 `sparse: true` | 빈 문자열이 아닌 undefined일 때만 unique 적용. `kakaoId: ''` 같은 값이 들어가면 두 번째 사용자에서 unique 충돌. callback에서 빈 값은 절대 저장하지 않도록 유지 |
| `src/app/login/page.tsx` | `Suspense` wrap of `LoginPageInner` | `useSearchParams`는 Next 14 build prerender에서 Suspense 경계 필수. 풀면 build 깨짐 |
